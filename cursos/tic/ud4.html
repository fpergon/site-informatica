1

Sistemas gestores de bases de datos relacionales. Qué es un SGBD. Modelo relacional

Nota didáctica Esta sesión inicial establece las bases conceptuales del modelo relacional. Es fundamental que el alumnado comprenda qué es un SGBD, por qué se usa el modelo relacional y cuáles son sus ventajas antes de manipular datos.

Introducción

Las bases de datos están en todas partes: desde los registros médicos de un hospital hasta el catálogo de productos de una tienda online. En esta sesión aprenderemos qué son las bases de datos, por qué son importantes y cómo funciona el modelo relacional, el más utilizado en el mundo.

¿Qué es una base de datos?

Una base de datos (BD) es un conjunto organizado de datos estructurados que se almacenan electrónicamente para facilitar su acceso, gestión y actualización. No es simplemente una lista de datos, sino una estructura diseñada para responder preguntas de forma eficiente.

  • Datos: Hechos brutos (nombres, números, fechas).
  • Información: Datos procesados y organizados con sentido.
  • Conocimiento: Información interpretada para la toma de decisiones.

¿Qué es un SGBD?

Un Sistema Gestor de Bases de Datos (SGBD) es el software que permite crear, administrar y manipular bases de datos. Actúa como intermediario entre el usuario y los datos almacenados:

  • Crear: Definir la estructura de la base de datos (tablas, campos, tipos de datos).
  • Manipular: Insertar, modificar, eliminar y consultar datos.
  • Gestionar: Controlar acceso, seguridad, integridad y recuperación.

SGBD relacionales más utilizados: MySQL, PostgreSQL, Microsoft SQL Server, Oracle, SQLite.

El modelo relacional

El modelo relacional organiza los datos en tablas (también llamadas relaciones). Cada tabla tiene:

  • Nombre: Identifica la tabla (ej: Alumnos, Pedidos).
  • Campos (columnas): Cada columna representa un tipo de dato (nombre, apellido, fecha_nacimiento).
  • Registros (filas): Cada fila representa un elemento concreto (un alumno, un pedido).
  • Clave primaria: Campo que identifica de forma única cada registro.
Ejemplo cotidiano Una tabla de "Contactos" del teléfono móvil es una base de datos simple: cada contacto es un registro, y campos como "Nombre", "Teléfono" y "Email" son las columnas.

Ventajas del modelo relacional

  • Integridad: Los datos son consistentes y fiables.
  • Redundancia mínima: Los datos se almacenan una sola vez.
  • Flexibilidad: Se pueden hacer consultas complejas entre tablas.
  • Seguridad: Control granular de acceso a datos.
  • Independencia: La estructura de la BD es independiente de las aplicaciones que la usan.
Actividad exploratoria Abrir SQLite Online (sqliteonline.com) y familiarizarse con la interfaz. Crear una tabla de prueba con 3 campos (id, nombre, email) e insertar 3 registros con INSERT.

2

Tablas, registros y campos. Tipos de datos. Estructura de una BD

Introducción

En esta sesión profundizaremos en la estructura de una base de datos relacional: cómo se diseñan las tablas, qué tipos de datos existen y cómo se organizan los registros para garantizar la integridad y eficiencia de los datos.

Estructura de una tabla

Cada tabla relacional debe seguir estas reglas:

  • Cada tabla tiene un nombre único dentro de la base de datos.
  • Cada campo tiene un tipo de datos que define qué información puede contener.
  • Cada registro es único (garantizado por la clave primaria).
  • Los valores de una columna son del mismo tipo (no mezclar texto y números en la misma columna).
  • El orden de filas y columnas no importa (la estructura es lógica, no física).

Tipos de datos

  • INTEGER (INT): Números enteros. Para IDs, cantidades, edades.
  • FLOAT / DOUBLE: Números con decimales. Para precios, pesos, medidas.
  • VARCHAR(n): Texto variable de hasta n caracteres. Para nombres, emails, descripciones.
  • TEXT: Texto largo sin límite de caracteres. Para comentarios, biografías.
  • DATE: Fechas en formato YYYY-MM-DD.
  • DATETIME / TIMESTAMP: Fecha y hora.
  • BOOLEAN (BOOL): Verdadero o falo (0 o 1).
  • DECIMAL(p,s): Números con precisión exacta (para dinero).
Elección del tipo de datos Usa el tipo más apropiado para cada campo: no uses VARCHAR para números, no uses INTEGER para fechas. Una buena elección de tipos ahorra espacio y mejora la eficiencia de las consultas.

Restricciones

Las restricciones garantizan la integridad de los datos:

  • PRIMARY KEY: Clave primaria. Identifica cada registro de forma única. No puede ser NULL ni duplicada.
  • NOT NULL: El campo no puede estar vacío.
  • UNIQUE: Todos los valores del campo deben ser diferentes.
  • DEFAULT(valor): Si no se proporciona un valor, se usa el predeterminado.
  • CHECK(condición): El valor debe cumplir una condición específica.

Diseño de una base de datos

El proceso de diseño sigue estos pasos:

  1. Identificar entidades: ¿Qué objetos del mundo real necesitamos representar? (Alumnos, Asignaturas, Profesores).
  2. Identificar atributos: ¿Qué información guardamos de cada entidad? (nombre, email, fecha_nacimiento).
  3. Definir claves primarias: ¿Qué campo identifica de forma única cada registro? (id_alumno, id_asignatura).
  4. Establecer relaciones: ¿Cómo se conectan las entidades entre sí?
Actividad práctica Crear en SQLite Online una tabla "Alumnos" con campos: id (INTEGER PRIMARY KEY), nombre (VARCHAR 50), apellido1 (VARCHAR 50), apellido2 (VARCHAR 50), fecha_nacimiento (DATE), email (VARCHAR 100). Insertar al menos 5 registros.

Claves y relaciones. Clave primaria, clave foránea. Relaciones 1:N y N:M

Introducción

La verdadera potencia de las bases de datos relacionales reside en la capacidad de conectar tablas entre sí mediante claves. En esta sesión estudiaremos los tipos de claves, las relaciones entre tablas y cómo se implementan en el modelo relacional.

Tipos de claves

  • Clave primaria (PK): Campo (o combinación de campos) que identifica de forma única cada registro. Ejemplo: id_alumno en la tabla Alumnos.
  • Clave foránea (FK): Campo en una tabla que hace referencia a la clave primaria de otra tabla. Establece la relación entre ambas. Ejemplo: id_alumno en la tabla Matriculas.
  • Clave candidata: Campo que podría ser clave primaria (tiene UNIQUE y NOT NULL).
  • Clave compuesta: Combinación de dos o más campos que forman la clave primaria.
Regla fundamental La clave primaria nunca puede ser NULL y debe ser única. La clave foránea debe coincidir con un valor existente en la tabla referenciada (integridad referencial) o ser NULL.

Relaciones 1:N (Uno a Muchos)

Es el tipo de relación más común. Un registro de la tabla A se relaciona con varios registros de la tabla B:

  • Un profesor imparte varias asignaturas. La clave foránea va en la tabla "Muchos" (Asignaturas).
  • Un cliente realiza varios pedidos. FK id_cliente en la tabla Pedidos.
  • Un departamento tiene varios empleados. FK id_departamento en la tabla Empleados.

Relaciones N:M (Muchos a Muchos)

Un registro de la tabla A se relaciona con varios de B, y viceversa. Se resuelve con una tabla intermedia (también llamada tabla de unión o asociación):

  • Alumnos se matriculan en varias Asignaturas (y cada Asignatura tiene varios Alumnos). Tabla intermedia: Matriculas con FK id_alumno y FK id_asignatura.
  • Productos se incluyen en varios Pedidos (y cada Pedido tiene varios Productos). Tabla intermedia: DetallePedido.
Diagrama de ejemplo Para una BD de biblioteca: Libros (1) → (N) Prestamos ← (N) Socios. La tabla Prestamos tiene FK id_libro y FK id_socio, resolviendo la relación N:M entre Libros y Socios.

Integridad referencial

La integridad referencial garantiza que las relaciones entre tablas sean válidas:

  • RESTRICT: Impide eliminar un registro si tiene registros dependientes.
  • CASCADE: Al eliminar un registro, elimina también los dependientes.
  • SET NULL: Al eliminar un registro, pone a NULL las FK dependientes.
  • SET DEFAULT: Al eliminar, asigna un valor predeterminado a las FK.

Lenguaje SQL. Sentencias DDL y DML. SELECT, INSERT, UPDATE, DELETE

Introducción

SQL (Structured Query Language) es el lenguaje estándar para interactuar con bases de datos relacionales. Permite crear estructuras, insertar datos, modificar registros y realizar consultas complejas. En esta sesión aprenderemos las sentencias fundamentales de SQL.

Sentencias DDL (Data Definition Language)

DDL se utiliza para definir y modificar la estructura de la base de datos:

  • CREATE TABLE: Crea una nueva tabla.
  • ALTER TABLE: Modifica la estructura de una tabla existente.
  • DROP TABLE: Elimina una tabla completamente.
  • CREATE INDEX: Crea un índice para búsquedas rápidas.

Ejemplo CREATE TABLE:

CREATE TABLE Alumnos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre VARCHAR(50) NOT NULL,
  apellido VARCHAR(50) NOT NULL,
  email VARCHAR(100) UNIQUE,
  fecha_nac DATE
);

Sentencias DML (Data Manipulation Language)

DML se utiliza para manipular los datos dentro de las tablas:

  • SELECT: Consulta y recupera datos.
  • INSERT INTO: Añade nuevos registros.
  • UPDATE: Modifica registros existentes.
  • DELETE: Elimina registros.

INSERT INTO

Para insertar datos en una tabla:

INSERT INTO Alumnos (nombre, apellido, email, fecha_nac)
VALUES ('Ana', 'García', 'ana@email.com', '2005-03-15');

INSERT INTO Alumnos (nombre, apellido, email, fecha_nac)
VALUES
  ('Carlos', 'López', 'carlos@email.com', '2004-11-20'),
  ('María', 'Martínez', 'maria@email.com', '2005-07-08');

SELECT (consultas básicas)

-- Seleccionar todos los campos
SELECT * FROM Alumnos;

-- Seleccionar campos específicos
SELECT nombre, apellido FROM Alumnos;

-- Con condición WHERE
SELECT * FROM Alumnos WHERE fecha_nac > '2005-01-01';

-- Ordenar resultados
SELECT * FROM Alumnos ORDER BY apellido ASC;

-- Limitar resultados
SELECT * FROM Alumnos LIMIT 5;

UPDATE y DELETE

-- Actualizar un registro
UPDATE Alumnos
SET email = 'ana.nuevo@email.com'
WHERE id = 1;

-- Eliminar un registro
DELETE FROM Alumnos WHERE id = 3;
Cuidado con DELETE Sin una cláusula WHERE, DELETE elimina TODOS los registros de la tabla. Siempre incluye WHERE a menos que quieras vaciar la tabla completamente.

5

Consultas avanzadas. JOIN, WHERE, ORDER BY, GROUP BY, funciones de agregado

Introducción

Las consultas avanzadas permiten extraer información compleja de múltiples tablas. Los JOIN son esenciales para combinar datos relacionados, y las funciones de agregado permiten resumir grandes volúmenes de datos en valores significativos.

JOIN (Unión de tablas)

Los JOIN permiten combinar registros de dos o más tablas basándose en una relación:

  • INNER JOIN: Devuelve solo los registros que tienen coincidencia en ambas tablas.
  • LEFT JOIN: Devuelve todos los registros de la tabla izquierda y los coincidentes de la derecha.
  • RIGHT JOIN: Devuelve todos los registros de la tabla derecha y los coincidentes de la izquierda.
  • CROSS JOIN: Combina cada registro de una tabla con cada registro de otra (producto cartesiano).
SELECT A.nombre, A.apellido, M.nota
FROM Alumnos A
INNER JOIN Matriculas M ON A.id = M.id_alumno
WHERE M.nota >= 6
ORDER BY M.nota DESC;
INNER JOIN vs LEFT JOIN INNER JOIN solo muestra alumnos matriculados. LEFT JOIN muestra TODOS los alumnos, incluyendo los que no tienen matrícula (con NULL en las columnas de la tabla derecha).

Funciones de agregado

Estas funciones resumen datos de múltiples registros:

  • COUNT(*): Cuenta el número de registros.
  • SUM(campo): Suma todos los valores.
  • AVG(campo): Calcula la media.
  • MAX(campo): Devuelve el valor máximo.
  • MIN(campo): Devuelve el valor mínimo.

GROUP BY y HAVING

GROUP BY agrupa registros con valores iguales en un campo, para usar con funciones de agregado:

-- Contar alumnos por género
SELECT genero, COUNT(*) as num_alumnos
FROM Alumnos
GROUP BY genero;

-- Media de nota por asignatura (solo notas ≥ 6)
SELECT id_asignatura, AVG(nota) as media
FROM Matriculas
GROUP BY id_asignatura
HAVING AVG(nota) >= 6;

Diferencia WHERE vs HAVING: WHERE filtra antes de agrupar, HAVING filtra después de agrupar.

Consejo práctico Para consultas complejas, constrúyelas paso a paso: primero el FROM, luego el JOIN, después el WHERE, luego el GROUP BY, después el HAVING, y finalmente el SELECT y ORDER BY.

Vistas, informes y formularios. Visualización e interacción con los datos

Introducción

Las vistas, informes y formularios son herramientas que facilitan la visualización e interacción con los datos de una base de datos. Mientras las vistas simplifican consultas complejas, los informes presentan datos de forma imprimible y los formularios permiten una fácil entrada de datos.

Vistas (Views)

Una vista es una consulta almacenada que se comporta como una tabla virtual:

  • No almacena datos: Ejecuta la consulta cada vez que se accede.
  • Simplifica consultas complejas: Un JOIN complicado se convierte en "SELECT * FROM vista".
  • Seguridad: Puede ocultar columnas sensibles (como contraseñas o salarios).
  • Consistencia: Garantiza que todos los usuarios ven los datos de la misma forma.
CREATE VIEW VistaAlumnosNotas AS
SELECT A.nombre, A.apellido, Asig.nombre as asignatura, M.nota
FROM Alumnos A
INNER JOIN Matriculas M ON A.id = M.id_alumno
INNER JOIN Asignaturas Asig ON M.id_asignatura = Asig.id;

-- Ahora se puede consultar como una tabla normal
SELECT * FROM VistaAlumnosNotas WHERE nota >= 6;

Informes

Los informes presentan datos de forma estructurada y lista para imprimir:

  • Encabezado: Título del informe, fecha, logo.
  • Cuerpo: Tablas de datos organizados.
  • Pie: Totales, promedios, información de pie de página.
  • Agrupaciones: Datos agrupados por categoría (ej: alumnos por clase).

Herramientas: Microsoft Access, LibreOffice Base, JasperReports.

Formularios

Los formularios facilitan la entrada y edición de datos con una interfaz gráfica amigable:

  • Campo de texto: Para introducir datos alfanuméricos.
  • Desplegable: Para seleccionar de una lista predefinida.
  • Casilla de verificación: Para valores verdadero/falso.
  • Botones: Guardar, eliminar, buscar, imprimir.
  • Validación: Comprobar que los datos cumplen un formato antes de guardar.
¿Cuándo usar cada uno? Vista: Para simplificar consultas recurrentes. Informe: Para imprimir o exportar datos formateados. Formulario: Para entrada y edición de datos por parte de usuarios no técnicos.

  2. Diseñar un formulario sencillo en papel para introducir nuevos alumnos.

Exportación e importación. Intercambio de datos entre sistemas

Introducción

Las bases de datos no trabajan aisladas. En esta sesión aprenderemos a exportar e importar datos entre diferentes sistemas y formatos, una habilidad esencial en el mundo real donde los datos provienen de múltiples fuentes.

Formatos de exportación

  • CSV: Texto plano con valores separados por comas. Universal, ligero, sin formato.
  • SQL: Script con sentencias SQL para recrear la estructura y datos.
  • JSON: Formato de intercambio web, jerárquico, legible por máquinas.
  • XML: Formato de marcado para intercambio de datos estructurados.
  • XLSX: Hoja de cálculo de Excel.
  • PDF: Para distribución e impresión.

Exportar desde SQLite

  • .output archivo.csv: Redirige la salida a un archivo.
  • .mode csv: Establece el modo de salida CSV.
  • SELECT * FROM tabla; Genera los datos en el formato seleccionado.
  • .quit: Cierra la sesión y guarda el archivo.
Intercambio con hojas de cálculo Un flujo de trabajo común es: exportar datos de la BD a CSV → importar en Google Sheets/Excel para análisis → exportar el resultado → importar de nuevo en la BD.

Importar datos

  • Desde CSV: .import archivo.csv nombre_tabla (en SQLite CLI).
  • Desde otro SGBD: Exportar en SQL e importar en el nuevo sistema.
  • Desde APIs: Usar scripts (Python, Node.js) para conectar con servicios web.
  • Desde archivos: Programas como DB Browser for SQLite permiten importar visualmente.

Buenas prácticas de intercambio

  • Verificar la integridad: Comprobar que los datos se importaron correctamente.
  • Codificación de caracteres: Usar UTF-8 para compatibilidad con tildes y caracteres especiales.
  • Respaldo: Siempre hacer una copia de seguridad antes de importar datos masivos.
  • Validación: Comprobar tipos de datos, formato de fechas y valores nulos.
Actividad práctica Exportar la base de datos de alumnos a un archivo CSV, abrirlo en Google Sheets, modificar algunos datos, guardar como CSV e importar de nuevo a SQLite. Verificar que los cambios se reflejan correctamente.

Proyecto final: base de datos relacional completa con consultas SQL

Proyecto de unidad Esta sesión está dedicada al desarrollo del proyecto final de la UD4. Cada alumno deberá crear una base de datos relacional completa que integre todas las competencias trabajadas a lo largo de las 7 sesiones anteriores.

Enunciado del proyecto

Crear una "Base de datos de Gestión de una Biblioteca Escolar" con los siguientes elementos:

  • Tablas: Socios, Libros, Prestamos, Categorias (mínimo 4 tablas).
  • Relaciones: Claves primarias y foráneas correctamente definidas. Al menos 2 relaciones 1:N y 1 N:M.
  • Datos: Insertar al menos 10 registros en cada tabla principal.
  • Consultas SQL: Crear al menos 8 consultas diferentes incluyendo JOIN, WHERE, GROUP BY, funciones de agregado.
  • Vistas: Crear al menos 2 vistas que simplifiquen consultas frecuentes.
  • Exportación: Exportar los datos de una consulta a CSV.
Criterios de evaluación Diseño de tablas y tipos de datos (20%), relaciones e integridad referencial (20%), calidad y variedad de consultas SQL (25%), uso de vistas (15%), documentación y presentación (20%).

Estructura de la BD

  • Socios: id, nombre, apellido, email, telefono, fecha_alta.
  • Categorias: id, nombre, descripcion.
  • Libros: id, titulo, autor, id_categoria, anio, isbn, disponibilidad.
  • Prestamos: id, id_socio, id_libro, fecha_prestamo, fecha_devolucion, devuelto.

Consultas sugeridas

  1. Listar todos los libros disponibles con su categoría.
  2. Mostrar los préstamos activos con datos del socio y del libro.
  3. Contar cuántos libros hay por categoría.
  4. Mostrar los socios que nunca han realizado un préstamo.
  5. Calcular el número total de préstamos por mes.
  6. Listar los libros más prestados (top 5).
  7. Mostrar los préstamos vencidos (fecha_devolución pasada y no devueltos).
  8. Calcular la media de días de préstamo por categoría.
