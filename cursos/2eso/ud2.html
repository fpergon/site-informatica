UD2 · Desarrollo de Aplicaciones Móviles

Aprender a desarrollar aplicaciones móviles utilizando entornos de desarrollo visual por bloques, comprendiendo la programación orientada a eventos, el manejo de sensores y la creación de interfaces interactivas. Esta unidad sentará las bases para el desarrollo móvil y la comprensión de cómo los dispositivos interactúan con el mundo real.

1

IDEs de bloques para móviles

Nota didáctica Esta sesión inicial presenta los entornos de desarrollo visual por bloques que utilizaremos durante la unidad. Es fundamental que el alumnado comprenda las características compartidas antes de empezar a crear sus primeras aplicaciones.

Introducción

El desarrollo de aplicaciones móviles ya no es exclusivo de programadores expertos. Gracias a los entornos de desarrollo visual por bloques, cualquier persona puede crear aplicaciones funcionales sin necesidad de escribir código complejo. En esta sesión exploraremos las principales plataformas disponibles y sus características compartidas que facilitan el proceso de creación.

Thunkable

Thunkable es una plataforma de desarrollo de aplicaciones móviles que utiliza un sistema de bloques visuales similar a Scratch. Permite crear aplicaciones para Android e iOS desde el navegador web. Sus principales ventajas incluyen una interfaz de arrastrar y soltar intuitiva, acceso directo a sensores del dispositivo, posibilidad de probar las aplicaciones en tiempo real mediante una aplicación companion, y exportación directa a tiendas de aplicaciones. Thunkable es ideal para principiantes porque ofrece plantillas prediseñadas y una curva de aprendizaje suave.

MIT App Inventor

MIT App Inventor es un proyecto del Instituto Tecnológico de Massachusetts que permite crear aplicaciones Android completamente funcionales. Utiliza un entorno de bloques similar a Scratch pero con bloques específicos para desarrollo móvil. Destaca por su comunidad activa, documentación extensa y integración directa con servicios de Google. Es gratuito y de código abierto, lo que lo hace muy popular en el ámbito educativo. El entorno incluye un emulador integrado para probar las aplicaciones en el ordenador.

AppyBuilder

AppyBuilder es otra plataforma de desarrollo visual que permite crear aplicaciones móviles sin programar. Ofrece una interfaz de bloques similar a App Inventor pero con algunas diferencias en la organización de los componentes. Es conocido por su facilidad de uso y por proporcionar plantillas de aplicaciones listas para personalizar. La plataforma incluye funcionalidades avanzadas como bases de datos en la nube y notificaciones push que permiten crear aplicaciones más complejas.

Características compartidas Todos estos entornos comparten características esenciales: interfaz visual de arrastrar y soltar, previsualización en tiempo real del diseño, acceso directo al hardware del dispositivo (cámara, GPS, acelerómetro), bloques predefinidos para lógica y eventos, y posibilidad de exportar a tiendas de aplicaciones.

Acceso a hardware

Una de las grandes ventajas de estos entornos es la capacidad de acceder directamente al hardware del dispositivo móvil. Podemos utilizar la cámara para capturar fotos o vídeos, el GPS para obtener la ubicación actual, el acelerómetro para detectar movimientos y orientación, el micrófono para grabar audio, y los sensores de proximidad y luz ambiental. Esta integración directa permite crear aplicaciones que interactúan con el mundo físico de manera significativa.

Bloques predefinidos

Los bloques predefinidos constituyen la base de la programación en estos entornos. Incluyen bloques para eventos (cuando el usuario pulsa un botón), bloques de control (si-entonces, bucles), bloques de lógica (y, o, no), bloques matemáticos (sumas, restas, comparaciones), bloques de texto (unir, dividir, convertir), y bloques específicos de cada componente (cámara, sensores, almacenamiento). Esta modularidad permite construir aplicaciones complejas combinando bloques simples.

2

Programación orientada a eventos

Nota didáctica La programación orientada a eventos es el paradigma fundamental del desarrollo móvil. Es crucial que el alumnado entienda el enfoque reactivo y las características que la definen antes de profundizar en los tipos de eventos.

Introducción

En el desarrollo de aplicaciones móviles, el usuario interactúa constantemente con la pantalla: pulsa botones, desliza, escribe y realiza gestos. La programación orientada a eventos es el paradigma que permite a las aplicaciones responder a estas interacciones de manera eficiente y fluida.

¿Qué es la programación orientada a eventos?

La programación orientada a eventos es un paradigma de programación en el que el flujo del programa está determinado por eventos. Un evento puede ser una acción del usuario (pulso de botón, deslizamiento), una señal del sistema (inicio de la aplicación, error) o una notificación externa (mensaje recibido, cambio de ubicación). En lugar de ejecutar instrucciones de forma secuencial, el programa espera a que ocurran eventos y ejecuta el código correspondiente cuando estos se producen.

Enfoque reactivo

El enfoque reactivo significa que la aplicación reacciona a los eventos que ocurren en lugar de controlar activamente el flujo. Por ejemplo, cuando un usuario pulsa un botón, se dispara un evento "onClick" que ejecuta una función específica. Este modelo es intuitivo porque refleja cómo interactuamos con las aplicaciones en la vida real: esperamos a que algo ocurra y respondemos en consecuencia.

Características principales

  • Asincronía: Los eventos pueden ocurrir en cualquier momento, sin un orden predefinido. La aplicación debe poder manejar múltiples eventos simultáneamente.
  • Encapsulamiento: Cada evento se maneja de forma independiente. El código de respuesta a un evento no afecta directamente a otros eventos.
  • Interfaz intuitiva: El programador solo necesita definir qué hacer cuando ocurra cada evento, sin preocuparse por el flujo general del programa.
  • Desacoplamiento: Los componentes de la aplicación están separados, lo que facilita el mantenimiento y las modificaciones.

Ventajas e inconvenientes

Ventajas: Facilita el desarrollo de interfaces de usuario interactivas, permite crear aplicaciones responsivas, simplifica la gestión de múltiples acciones simultáneas, y es más fácil de aprender para principiantes porque se parece a la forma natural de interactuar con los dispositivos.

Inconvenientes: Puede ser difícil de depurar cuando hay muchos eventos anidados, el flujo del programa no es lineal lo que complica la comprensión global, y puede generar código duplicado si no se gestionan correctamente las funciones de respuesta.

Ejemplo práctico

Consideremos una aplicación sencilla con dos botones: uno para cambiar el color de fondo y otro para mostrar un mensaje. En programación orientada a eventos, definiríamos dos manejadores de eventos: uno que se ejecuta al pulsar el primer botón (cambia el color) y otro que se ejecuta al pulsar el segundo botón (muestra el mensaje). Cada evento se maneja de forma independiente.

Reflexión ¿Qué diferencias encontráis entre programar de forma secuencial (como en Scratch básico) y programar de forma orientada a eventos? ¿En qué situaciones sería más útil cada enfoque?
3

Dependencia de eventos

Nota didáctica En esta sesión analizaremos cómo los eventos pueden depender unos de otros, creando cadenas de eventos. El ejemplo de TikTok ayudará a visualizar este concepto de forma práctica y familiar.

Introducción

En las aplicaciones móviles, los eventos no ocurren de forma aislada. Muchas veces, un evento dispara otro, que a su vez activa otro, creando una cadena de eventos interdependientes. Comprender esta dependencia es clave para diseñar aplicaciones que funcionen correctamente en escenarios reales.

¿Qué es la cadena de eventos?

Una cadena de eventos es una secuencia donde cada evento es consecuencia del anterior. Por ejemplo, al abrir una aplicación de mensajería: primero se inicia la sesión (evento 1), luego se carga la lista de contactos (evento 2), después se selecciona un contacto (evento 3) y finalmente se envía un mensaje (evento 4). Cada paso depende del anterior y sin completar el paso anterior, el siguiente no puede ejecutarse.

Ejemplo: TikTok

Tomemos como ejemplo TikTok, una aplicación que todos conocemos. Analicemos la cadena de eventos completa:

  1. Inicio de sesión: El usuario abre la aplicación y se autentica (evento de usuario).
  2. Selección de contenido: El usuario elige si crear un nuevo vídeo o ver los existentes.
  3. Carga de recursos: Si elige crear, la aplicación accede a la cámara y al micrófono (evento de sistema).
  4. Edición: El usuario graba, añade efectos y música (eventos de usuario y sensores).
  5. Publicación: El vídeo se sube a los servidores de TikTok (evento de red).
  6. Visualización: Otros usuarios pueden ver y reaccionar al vídeo (eventos de usuario).
  7. Interacción: Los usuarios pueden comentar, compartir o dar "me gusta" (eventos de usuario).
Observa la cadena Cada paso de esta cadena depende del anterior. Si falla la conexión a Internet en el paso 5 (publicación), los pasos 6 y 7 no pueden ejecutarse. Esto demuestra la importancia de manejar correctamente las dependencias entre eventos.

Gestión de errores en cadenas

Cuando una cadena de eventos falla en algún punto, es fundamental tener un plan de contingencia. Por ejemplo, si la publicación del vídeo falla por falta de conexión, la aplicación debería guardar el vídeo localmente y intentarlo más tarde, o mostrar un mensaje de error claro al usuario. Los bloqueos en cadenas de eventos son una de las causas más comunes de problemas en aplicaciones móviles.

Actividad práctica

En grupos de 3-4 alumnos, vais a diseñar la cadena de eventos de una aplicación de música (como Spotify). Identificad al menos 5 eventos consecutivos desde que el usuario abre la aplicación hasta que reproduce una canción. Indicad qué tipo de evento es cada uno (usuario, sistema, red).

4

Tipos de eventos

Nota didáctica Esta sesión clasifica los diferentes tipos de eventos que pueden ocurrir en una aplicación móvil. Es importante que el alumnado distinga entre ellos para poder diseñar sus propias aplicaciones de manera efectiva.

Introducción

Los eventos en las aplicaciones móviles pueden clasificarse en varias categorías según su origen y naturaleza. Conocer estos tipos nos permite diseñar aplicaciones más robustas y preparadas para diferentes situaciones.

Vídeo recomendado Mira este vídeo para profundizar en los diferentes tipos de eventos en desarrollo móvil:

Eventos de usuario

Son los más comunes y directos. Se originan por la interacción física del usuario con el dispositivo. Incluyen pulsaciones de botones, deslizamientos en la pantalla (swipe), pellizcos para zoom, escritura en campos de texto, selección de elementos en listas, gestos personalizados como doble pulsación o pulsación larga, y navegación entre pantallas. Estos eventos son predecibles y el programador puede anticiparlos fácilmente.

Eventos de sistema

Son generados por el propio sistema operativo del dispositivo. Incluyen el inicio y cierre de la aplicación, cambios en la orientación de la pantalla (horizontal a vertical), recepción de llamadas o mensajes, cambios en la conexión de red (WiFi a datos móviles), bajo nivel de batería, y notificaciones de otros procesos. Estos eventos son menos predecibles y requieren manejo cuidadoso para evitar interrumpir la experiencia del usuario.

Eventos de tiempo

Son generados por el paso del tiempo o por temporizadores programados. Ejemplos incluyen actualizaciones periódicas de contenido, animaciones que se ejecutan cada cierto intervalo, recordatorios programados, temporizadores de cuenta atrás, y actualización de la ubicación cada N segundos. Estos eventos son útiles para mantener la aplicación actualizada sin intervención del usuario.

Eventos de sensores

Son generados por los sensores físicos del dispositivo. Incluyen el acelerómetro (detecta movimiento y orientación), el giroscopio (detecta rotación), el GPS (proporciona ubicación), el sensor de proximidad (detecta objetos cercanos), el sensor de luz (mide luminosidad ambiental), y el barómetro (mide presión atmosférica). Estos eventos permiten crear aplicaciones que interactúan con el entorno físico.

Eventos de red

Son generados por la conexión a Internet o por la ausencia de ella. Incluyen la recepción de datos de servidores, la actualización de contenido en tiempo real, la sincronización de datos entre dispositivos, la pérdida de conexión, y la reconexión automática. Estos eventos son fundamentales para aplicaciones que dependen de datos en línea como redes sociales o aplicaciones de mensajería.

5

Eventos de entrada y salida (E/S)

Nota didáctica Esta sesión profundiza en los eventos de entrada (input) y salida (output) que son fundamentales para la interacción usuario-aplicación. La tabla de ejemplo de una app de compras ayudará a visualizar estos conceptos en un contexto real.

Introducción

En el desarrollo de aplicaciones móviles, la interacción se divide fundamentalmente en dos tipos: entradas (lo que el usuario proporciona a la aplicación) y salidas (lo que la aplicación muestra o comunica al usuario). Comprender esta distinción es esencial para crear interfaces intuitivas y funcionales.

Eventos de entrada (input)

Las entradas son las acciones que realiza el usuario para comunicarse con la aplicación. Los tipos principales incluyen:

  • Toques: Pulsaciones simples en botones, iconos o elementos de la interfaz.
  • Gestos: Acciones más complejas como deslizamientos (swipe), pellizcos (pinch), rotación con dos dedos, pulsación larga, y arrastrar y soltar.
  • Voz: Comandos de voz o dictado mediante el micrófono del dispositivo.
  • Escritura: Introducción de texto en campos de formulario, búsqueda o mensajes.
  • Sensores: Movimiento del dispositivo, orientación, ubicación geográfica.

Eventos de salida (output)

Las salidas son las respuestas que proporciona la aplicación al usuario. Los tipos principales incluyen:

  • Visuales: Textos, imágenes, animaciones, cambios de color, notificaciones en pantalla.
  • Auditivas: Sonidos, vibraciones, alertas sonoras.
  • Táctiles: Vibración del dispositivo para confirmar acciones o alertar.

6

Sensores como generadores de eventos

Nota didáctica Los sensores son componentes físicos del dispositivo que permiten a las aplicaciones interactuar con el entorno real. Esta sesión es fundamental para el proyecto final donde el alumnado deberá incorporar sensores en sus aplicaciones.

Introducción

Los dispositivos móviles modernos incluyen una variedad de sensores que miden aspectos del entorno físico. Estos sensores generan eventos que las aplicaciones pueden utilizar para crear experiencias interactivas y contextuales. Comprender cómo funcionan estos sensores es esencial para el desarrollo de aplicaciones innovadoras.

Acelerómetro

El acelerómetro mide la aceleración del dispositivo en tres ejes (X, Y, Z). Detecta cuando el dispositivo se mueve, cambia de orientación o vibra. Ejemplos de uso: Juegos que responden al movimiento del dispositivo (como un tenis de mesa virtual), aplicaciones de fitness que cuentan pasos, detección de caídas para aplicaciones de seguridad, y control de reproducción de música con gestos del dispositivo.

Giroscopio

El giroscopio mide la velocidad de rotación del dispositivo en tres ejes. Proporciona información más precisa que el acelerómetro para detectar rotaciones. Ejemplos de uso: Realidad aumentada donde el contenido se ajusta según la orientación del dispositivo, navegación interior en edificios, y juegos que requieren precisión en los movimientos de rotación.

GPS (Global Positioning System)

El GPS proporciona la ubicación geográfica exacta del dispositivo (latitud, longitud, altitud). Ejemplos de uso: Aplicaciones de mapas y navegación (Google Maps), rastreo de actividad física (registra rutas y distancias), geolocalización de fotos, y servicios basados en la ubicación (restaurantes cercanos).

Sensor de proximidad

Detecta la presencia de objetos cercanos sin contacto físico. Normalmente se utiliza para apagar la pantalla durante las llamadas telefónicas. Ejemplos de uso: Apagar la pantalla automáticamente cuando el usuario se lleva el dispositivo al oído, activar funciones cuando el usuario se acerca al dispositivo, y detección de gestos sin contacto.

Sensor de luz

Mide la intensidad de la luz ambiental que incide sobre el dispositivo. Ejemplos de uso: Ajuste automático del brillo de la pantalla según las condiciones de iluminación, activación del modo nocturno en la oscuridad, y control inteligente del consumo de energía.

Barómetro

Mide la presión atmosférica. Permite determinar la altitud del dispositivo. Ejemplos de uso: Aplicaciones de senderismo que muestran la altitud actual, predicción meteorológica local, y mejora de la precisión del GPS en ubicaciones verticales (edificios con múltiples plantas).

Ejemplos reales Las aplicaciones de realidad aumentada como Pokémon Go utilizan acelerómetro, giroscopio y GPS simultáneamente. Las aplicaciones de salud como Samsung Health combinan acelerómetro y giroscopio para detectar tipos de actividad física. Las aplicaciones de clima utilizan barómetro y GPS para提供 predicciones localizadas.

Actividad práctica

Utilizando Thunkable o MIT App Inventor, cread una aplicación sencilla que muestre los valores actuales del acelerómetro y el sensor de luz en tiempo real. La aplicación debería actualizar los valores cada segundo y mostrar si el dispositivo está en movimiento y el nivel de luminosidad ambiental.

Proyecto final: App interactiva con Thunkable

Nota didáctica Esta sesión está dedicada a la presentación y desarrollo del proyecto final de la unidad. Los alumnos aplicarán todos los conceptos aprendidos para crear una aplicación completa con interacción y sensores.

Introducción

El proyecto final de esta unidad consiste en diseñar y desarrollar una aplicación móvil completa utilizando Thunkable. La aplicación debe incorporar los conceptos estudiados: programación orientada a eventos, manejo de diferentes tipos de eventos, integración de sensores, y una interfaz de usuario intuitiva y funcional.

Requisitos del proyecto

  • Interfaz visual: Diseño atractivo y coherente con al menos 3 pantallas diferentes.
  • Interacción de usuario: Uso de al menos 3 tipos de eventos de usuario (pulsaciones, deslizamientos, gestos).
  • Sensores: Incorporación de al menos 2 sensores del dispositivo (acelerómetro, GPS, luz, etc.).
  • Cadena de eventos: Implementación de al menos una cadena de eventos donde un evento active a otro.
  • Eventos de salida: Uso de al menos 2 tipos de salida (visual, auditiva, táctil).
  • Funcionalidad completa: La aplicación debe realizar una tarea concreta y útil.

Ejemplos de proyectos

Algunas ideas de aplicaciones que cumplen estos requisitos:

  • Aplicación de ejercicio: Registra actividad física usando acelerómetro y GPS, muestra estadísticas visuales.
  • Juego de orientación: Usa giroscopio y acelerómetro para controlar un objeto en pantalla.
  • Aplicación de clima local: Utiliza GPS y barómetro para proporcionar información meteorológica precisa.
  • Instrumento musical virtual: Usa acelerómetro para generar sonidos según la orientación del dispositivo.
  • Aplicación de seguridad: Detecta caídas con acelerómetro y envía alertas con ubicación GPS.
Consejos para el desarrollo Comenzad con el diseño de la interfaz antes de programar. Dividid el proyecto en tareas pequeñas y probad cada funcionalidad antes de pasar a la siguiente. Documentad las decisiones de diseño y los problemas encontrados para la presentación final.

Evaluación del proyecto

El proyecto se evaluará según los siguientes criterios:

  • Diseño de interfaz (20%): Coherencia visual, usabilidad, diseño atractivo.
  • Programación de eventos (30%): Correcto uso de eventos de usuario, sistema y sensores.
  • Funcionalidad (30%): La aplicación realiza su tarea de forma completa y correcta.
  • Presentación (20%): Explicación clara del funcionamiento y justificación de las decisiones técnicas.

Cronograma de trabajo
