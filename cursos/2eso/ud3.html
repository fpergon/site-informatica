1

Estructura básica de una página web

Sesión 1 · 50 minutos

Nota didáctica Esta sesión es el punto de partida del desarrollo web. Es fundamental que el alumnado comprenda la diferencia entre estructura (HTML) y presentación (CSS) antes de avanzar a temas más complejos como la interacción con servidores o la animación.

Introducción

¿Alguna vez os habéis preguntado cómo se crean las páginas web que visitáis a diario? Detrás de cada sitio web hay un conjunto de tecnologías que trabajan juntas para mostrar contenido en vuestro navegador. En esta primera sesión vamos a desentrañar la estructura básica de una página web, desde el encabezado hasta el cuerpo, incluyendo elementos multimedia, enlaces y secciones que organizan la información de forma lógica y accesible.

¿Qué es HTML?

HTML (HyperText Markup Language) es el lenguaje de marcado que define la estructura y el contenido de una página web. No es un lenguaje de programación, sino un sistema de etiquetas que indica al navegador cómo organizar y mostrar la información. Cada página web que visitáis está construida con HTML como base fundamental.

Un documento HTML se compone de etiquetas que encierran contenido. Las etiquetas se escriben entre corchetes angulares y la mayoría tienen una etiqueta de apertura y otra de cierre. Por ejemplo, <h1>Título</h1> define un encabezado de primer nivel.

Estructura de un documento HTML

Todo documento HTML sigue una estructura jerárquica que comienza con la declaración del tipo de documento y se organiza en dos bloques principales:

  • <!DOCTYPE html>: Indica al navegador que el documento es HTML5.
  • <html>: Elemento raíz que contiene todo el documento.
  • <head>: Contiene metadatos, título, enlaces a hojas de estilo y scripts.
  • <body>: Contiene todo el contenido visible de la página.

Encabezados y cuerpo

Los encabezados son elementos que organizan la información jerárquicamente. HTML ofrece seis niveles de encabezados, desde <h1> (el más importante) hasta <h6> (el menos importante). Usar encabezados correctamente mejora la accesibilidad y el posicionamiento en buscadores.

El cuerpo de la página (<body>) contiene todos los elementos visibles: párrafos (<p>), listas (<ul>, <ol>), imágenes (<img>), enlaces (<a>) y mucho más.

Elementos multimedia

Las páginas web modernas incluyen contenido multimedia enriquecido. Los elementos principales son:

  • Imágenes (<img>): Muestran fotos, ilustraciones o gráficos. Requieren atributo src con la ruta y alt con descripción para accesibilidad.
  • Vídeos (<video>): Reproducen archivos de vídeo directamente en la página.
  • Audio (<audio>): Reproduce contenido de sonido como podcasts o música.
  • IFrames (<iframe>): Embeben contenido externo como mapas de Google o vídeos de YouTube.

Enlaces

Los enlaces son la base de la navegación en Internet. Sin enlaces, las páginas web serían documentos aislados. El elemento <a> (anchor) permite conectar páginas entre sí. El atributo href especifica la dirección de destino. Los enlaces pueden ser absolutos (URL completa) o relativos (ruta dentro del mismo sitio).

Secciones y layout

HTML5 introdujo elementos semánticos que permiten estructurar el contenido de forma lógica: <header>, <nav>, <main>, <section>, <article>, <aside> y <footer>. Estos elementos no solo mejoran la semántica del documento, sino que facilitan el diseño y la accesibilidad.

Consejo práctico Para practicar, abrid el Bloc de Notas o VS Code y escribid una página HTML sencilla con un encabezado, un párrafo, una imagen y un enlace. Guardad el archivo como index.html y abridlo en vuestro navegador con doble clic. Ver cómo el navegador interpreta vuestro código es la mejor forma de aprender.

Actividad práctica

En esta sesión vais a crear vuestra primera página web. Debe incluir:

  1. Un encabezado principal con vuestro nombre.
  2. Un párrafo que os describa brevemente.
  3. Una imagen con texto alternativo descriptivo.
  4. Al menos dos enlaces a sitios web de vuestra interés.
  5. Una sección con una lista ordenada de vuestros cinco sitios web favoritos.

Servidores web: solicitud HTTP y renderizado

Sesión 2 · 50 minutos

Concepto clave Cada vez que escribís una URL en el navegador, se desencadena una cadena compleja de eventos que involucra servidores de nombres de dominio, servidores web y el motor de renderizado del navegador. Entender este proceso es esencial para comprender cómo funciona Internet.

Introducción

¿Qué ocurre exactamente cuando escribís "www.google.com" en la barra de direcciones y pulsáis Enter? En menos de un segundo suceden decenas de procesos que van desde la resolución del nombre de dominio hasta la renderización completa de la página. En esta sesión vamos a desglosar cada uno de estos pasos para entender cómo el navegador se comunica con los servidores web.

¿Qué es un servidor web?

Un servidor web es un ordenador que está encendido las 24 horas del día, 7 días a la semana, y que almacena archivos (páginas web, imágenes, vídeos, bases de datos) y los entrega a los navegadores que los solicitan. Cuando visitáis una web, en realidad estáis descargando archivos que están almacenados en un servidor remoto.

Los servidores web utilizan protocolos de comunicación para transferir datos. El más común es HTTP (HyperText Transfer Protocol) y su versión segura HTTPS, que cifra la comunicación entre el navegador y el servidor.

Resolución DNS

El DNS (Domain Name System) es como una guía telefónica de Internet. Los ordenadores se comunican entre sí usando direcciones IP (números como 142.250.185.78), pero los seres humanos recordamos mejor los nombres de dominio. El DNS se encarga de traducir "www.google.com" a su dirección IP correspondiente.

El proceso de resolución DNS sigue estos pasos:

  • El navegador consulta su caché de DNS local.
  • Si no lo encuentra, consulta el caché del sistema operativo.
  • Si tampoco, consulta el servidor DNS configurado por el proveedor de Internet.
  • Si aún no lo resuelve, contacta con los servidores raíz de DNS de la jerarquía mundial.
Dato curioso Cada día se realizan más de 5.000 millones de consultas DNS en todo el mundo. Sin el sistema DNS, tendríamos que memorizar direcciones IP numéricas para cada sitio web que quisiéramos visitar. ¡Sería imposible!

La solicitud HTTP

Una vez resuelto el nombre de dominio, el navegador envía una solicitud HTTP al servidor. Esta solicitud contiene información como el tipo de navegador, las cookies, los encabezados de aceptación y el método HTTP utilizado. Los métodos principales son:

  • GET: Solicita un recurso al servidor. Es el método más común.
  • POST: Envía datos al servidor (formularios, archivos).
  • PUT: Actualiza un recurso existente en el servidor.
  • DELETE: Elimina un recurso en el servidor.

Procesamiento y respuesta del servidor

El servidor recibe la solicitud, la procesa y devuelve una respuesta HTTP que incluye un código de estado y el contenido solicitado. Los códigos de estado más conocidos son:

  • 200 OK: La solicitud fue exitosa.
  • 301 Redirección: El recurso se ha movido permanentemente.
  • 404 Not Found: El recurso solicitado no existe.
  • 500 Error interno: El servidor encontró un error inesperado.

Renderizado en el navegador

El navegador recibe los archivos HTML, CSS y JavaScript y ejecuta un proceso de renderizado que convierte el código en la página visual que vemos. Este proceso incluye:

  1. Parseo del DOM: El navegador lee el HTML y construye el Árbol del DOM (Document Object Model).
  2. Parseo del CSSOM: Se procesan las hojas de estilo para construir el Árbol de CSS.
  3. Construcción del árbol de renderizado: Se combinan DOM y CSSOM.
  4. Layout (diseño): Se calcula la posición y tamaño de cada elemento.
  5. Pintura: Se dibujan los píxeles en la pantalla.
  6. Composición: Se superponen las capas en el orden correcto.

Actividad práctica

Vamos a usar las Herramientas de Desarrollador del navegador (F12) para inspeccionar:

  1. Abrir la pestaña Network y ver las solicitudes HTTP al cargar una página.
  2. Inspeccionar los encabezados de la solicitud y la respuesta.
  3. Observar el tiempo que tarda cada recurso en cargarse.
  4. Analizar el árbol DOM generado por el navegador.
Reflexión ¿Qué pasaría si el servidor de una web que utilizamos a diario se cae? ¿Cómo afectaría a los servicios que dependen de ella (correo, redes sociales, banca)? Reflexionad sobre la dependencia que tenemos de los servidores web en nuestra vida cotidiana.

Lenguajes web: HTML, CSS, PHP, JavaScript, SQL

Sesión 3 · 50 minutos

Concepto fundamental Cada lenguaje web tiene un papel específico en el ecosistema del desarrollo web. Comprender las diferencias entre estructura, estilo, lógica de cliente, lógica de servidor y almacenamiento de datos es clave para diseñar aplicaciones web completas y eficientes.

Introducción

El desarrollo web utiliza múltiples lenguajes que trabajan conjuntamente para crear experiencias completas. En esta sesión vamos a analizar las diferencias fundamentales entre los lenguajes más utilizados: HTML para la estructura, CSS para el estilo, PHP y JavaScript para la programación, y SQL para la gestión de datos. Cada uno resuelve un problema diferente y todos son necesarios para construir una aplicación web moderna.

HTML vs CSS: Estructura vs Estilo

HTML se encarga de la estructura y el contenido. Define qué hay en la página: títulos, párrafos, imágenes, enlaces y formularios. Es como los cimientos y la estructura de un edificio.

CSS (Cascading Style Sheets) se encarga de la presentación visual. Define colores, fuentes, tamaños, espaciados, posicionamiento y animaciones. Es como la pintura, el mobiliario y la decoración del edificio.

La separación entre HTML y CSS es un principio fundamental del desarrollo web moderno. Permite modificar el aspecto visual sin alterar la estructura del contenido, y facilita el mantenimiento y la accesibilidad.

PHP vs JavaScript: Servidor vs Cliente

PHP es un lenguaje de programación del lado del servidor. Se ejecuta en el servidor web antes de enviar la respuesta al navegador. Su principal ventaja es que puede acceder a bases de datos, generar contenido dinámico y manejar autenticación de usuarios de forma segura, ya que el código nunca se ve en el navegador.

JavaScript es un lenguaje de programación del lado del cliente. Se ejecuta directamente en el navegador del usuario. Permite crear interfaces interactivas, validar formularios, actualizar contenido sin recargar la página y crear animaciones. También puede ejecutarse en el servidor con Node.js.

SQL vs NoSQL

SQL (Structured Query Language) es el lenguaje estándar para gestionar bases de datos relacionales. Los datos se organizan en tablas con filas y columnas, y las relaciones entre tablas se establecen mediante claves. Ejemplos: MySQL, PostgreSQL, SQLite.

NoSQL son bases de datos que no siguen el modelo relacional. Se utilizan para grandes volúmenes de datos no estructurados. Tipos principales: documentos (MongoDB), clave-valor (Redis), columnas (Cassandra) y grafos (Neo4j).

Consejo práctico Imaginad una aplicación web como una restaurante. El HTML es la carta (contenido), el CSS es la decoración del local (estilo), JavaScript es el camarero que interactúa con vosotros en la mesa (cliente), PHP es el cocinero que prepara los platos en la cocina (servidor), y SQL es la despensa donde se almacenan los ingredientes (datos).

HTML en profundidad: semántica, multimedia y formularios

Sesión 4 · 50 minutos

Importancia de la semántica Utilizar las etiquetas semánticas correctas no es solo una cuestión de buenas prácticas. Los lectores de pantalla para personas con discapacidad visual, los motores de búsqueda y los navegadores dependen de la semántica para interpretar correctamente el contenido de una página web.

Introducción

HTML5 trajo consigo una serie de etiquetas semánticas que revolutionaron la forma en que estructuramos el contenido web. En esta sesión profundizaremos en estas etiquetas, aprenderemos a incorporar elementos multimedia de forma accesible y a crear formularios interactivos que permitan la recogida de datos del usuario.

Etiquetas semánticas

Las etiquetas semánticas de HTML5 comunican el significado del contenido al navegador y a las herramientas de asistencia:

  • <header>: Cabecera de la página o de una sección. Suele contener_logo, título y navegación principal.
  • <nav>: Contiene los enlaces de navegación principales del sitio.
  • <main>: Contenido principal de la página. Solo debe haber uno por documento.
  • <section>: Sección temática del contenido, con un tema o propósito definido.
  • <article>: Contenido independiente que puede distribuirse por su cuenta (noticia, entrada de blog).
  • <aside>: Contenido complementario, como barra lateral o información adicional.
  • <footer>: Pie de página o de sección. Contiene información de copyright, contacto, enlaces legales.
  • <figure> y <figcaption>: Agrupan contenido ilustrativo con su leyenda.

Elementos multimedia avanzados

HTML5 permite incorporar multimedia de forma nativa sin depender de plugins externos como Flash:

  • <video>: Reproduce vídeos con controles nativos. Atributos: controls, autoplay, loop, muted, poster.
  • <audio> reproduce contenido de sonido con controles integrados.
  • <source>: Define múltiples formatos de archivo dentro de un vídeo o audio para compatibilidad cruzada.
  • <iframe>: Embebe contenido externo como mapas, vídeos de plataformas o widgets.

Formularios HTML

Los formularios son el mecanismo principal para recoger información del usuario. Un formulario se define con <form> y contiene diferentes tipos de campos:

  • <input type="text">: Campo de texto para entrada libre.
  • <input type="email">: Validación automática de dirección de correo electrónico.
  • <input type="password">: Campo oculto para contraseñas.
  • <input type="number">: Campo numérico con controles incrementales.
  • <input type="date">: Selector de fecha con calendario nativo.
  • <textarea>: Campo de texto multilínea.
  • <select> y <option>: Menú desplegable de selección.
  • <input type="checkbox">: Casilla de verificación.
  • <input type="radio">: Botón de opción (selección múltiple exclusiva).
  • <button type="submit">: Botón de envío del formulario.
Buena práctica Siempre debéis incluir la etiqueta <label> asociada a cada campo del formulario mediante el atributo for. Esto mejora la accesibilidad para usuarios de lectores de pantalla y facilita la interacción en dispositivos táctiles.

Actividad práctica

Crear una página web de perfil personal que incluya:

  1. Estructura completa con etiquetas semánticas (<header>, <nav>, <main>, <section>, <footer>).
  2. Un vídeo embebido de YouTube usando <iframe>.
  3. Un formulario de contacto con al menos 5 tipos de campo diferentes.
  4. Una galería de imágenes usando <figure> y <figcaption>.
Accesibilidad Recordad que una página web bien construida debe ser accesible para todos. Incluir textos alternativos en imágenes, etiquetas en formularios y una estructura lógica de encabezados son requisitos mínimos para garantizar que todas las personas puedan acceder al contenido.

CSS en profundidad: selectores, modelo de cajas, Flexbox y Grid

Sesión 5 · 50 minutos

Concepto esencial El modelo de cajas (box model) es el pilar fundamental de CSS. Cada elemento en una página web es un rectángulo compuesto por contenido, relleno, borde y margen. Comprender este modelo es imprescindible para controlar el diseño y la distribución de elementos en la pantalla.

Introducción

CSS es el lenguaje que transforma un documento HTML plano en una página web visualmente atractiva. En esta sesión profundizaremos en los selectores que nos permiten dirigirnos a elementos específicos, el modelo de cajas que gobierna el espacio que ocupan los elementos, y los sistemas de diseño Flexbox y Grid que revolutionaron la distribución de contenido en la web moderna.

Selectores CSS

Los selectores determinan a qué elementos se aplican los estilos. Los tipos principales son:

  • Selector de elemento: p { color: blue; } — Aplica a todos los párrafos.
  • Selector de clase: .destacado { font-weight: bold; } — Aplica a elementos con class="destacado".
  • Selector de ID: #cabecera { background: white; } — Aplica al elemento con id="cabecera".
  • Selector descendente: nav a { text-decoration: none; } — Aplica a enlaces dentro de nav.
  • Selector hijo: ul > li { list-style: disc; } — Solo hijos directos.
  • Pseudo-clases: a:hover { color: red; } — Estado especial del elemento.

Propiedades CSS fundamentales

Las propiedades más utilizadas en el diseño web incluyen:

  • Tipografía: font-family, font-size, font-weight, line-height, text-align.
  • Colores: color, background-color, opacity.
  • Espaciado: margin, padding, gap.
  • Tamaño: width, height, max-width, min-height.
  • Bordes: border, border-radius, box-shadow.
  • Posicionamiento: position, top, left, z-index.
Consejo práctico Para comprender visualmente el modelo de cajas, activad la opción "Show box model" en las Herramientas de Desarrollador del navegador (F12 → pestaña Computed). Veréis representado gráficamente el contenido, padding, border y margin de cada elemento que seleccionéis.

Flexbox

Flexbox es un sistema de diseño unidimensional que facilita la alineación y distribución de elementos dentro de un contenedor. Es ideal para diseño de filas o columnas. Las propiedades principales son:

  • En el contenedor: display: flex, justify-content, align-items, flex-direction, flex-wrap, gap.
  • En los elementos hijos: flex-grow, flex-shrink, flex-basis, align-self, order.

CSS Grid

CSS Grid es un sistema de diseño bidimensional que permite crear estructuras complejas con filas y columnas simultáneamente. Es ideal para layouts de página completa. Las propiedades principales son:

  • En el contenedor: display: grid, grid-template-columns, grid-template-rows, grid-gap.
  • En los elementos hijos: grid-column, grid-row, grid-area.
Flexbox vs Grid Usad Flexbox para distribuir elementos en una dimensión (una fila o una columna) y CSS Grid cuando necesitáis controlar filas y columnas simultáneamente. Ambos son complementarios y se usan frecuentemente juntos en el desarrollo web profesional.

Actividad práctica

Crear un layout de página web utilizando CSS Grid y Flexbox:

  1. Diseñar una cabecera con Flexbox que centre el título y los enlaces de navegación.
  2. Crear una rejilla de 3 columnas con CSS Grid para mostrar tarjetas de contenido.
  3. Implementar una barra lateral que se oculte en pantallas pequeñas usando @media.
  4. Aplicar al menos 5 selectores diferentes para estilos específicos.

Animación web: CSS, JavaScript, SVG y Canvas

Sesión 6 · 50 minutos

Las animaciones web Las animaciones no son solo decoración. Cuando se usan correctamente, mejoran la experiencia de usuario, guían la atención, proporcionan retroalimentación y hacen que las interfaces se sientan más naturales y responsivas.

Introducción

Las animaciones son una parte fundamental del diseño web moderno. Desde una simple transición de color al pasar el cursor sobre un botón hasta complejas animaciones interactivas, las técnicas de animación web permiten crear experiencias dinámicas y envolventes. En esta sesión exploraremos las diferentes tecnologías disponibles: CSS transitions y keyframes, JavaScript, SVG, Canvas y WebGL.

CSS Transitions

Las transiciones CSS son la forma más sencilla de animar cambios en las propiedades de un elemento. Permiten definir una duración, una función de temporización y un retraso para la transición entre dos estados:

  • transition-property: Qué propiedad se anima (color, opacity, transform...).
  • transition-duration: Cuánto dura la transición (0.3s, 1s...).
  • transition-timing-function: Cómo se distribuye el tiempo (ease, linear, ease-in-out).
  • transition-delay: Cuánto tiempo espera antes de comenzar.

Son ideales para hover effects, cambios de estado y micro-interacciones simples.

CSS Keyframes

Las animaciones con keyframes permiten crear secuencias de movimiento más complejas definiendo múltiples puntos intermedios (keyframes) a lo largo de la animación:

  • @keyframes: Define los estilos en cada momento de la animación.
  • animation-name: Referencia al nombre del keyframe.
  • animation-duration: Duración total de la animación.
  • animation-iteration-count: Cuántas veces se repite (número o infinite).
  • animation-direction: Dirección (normal, reverse, alternate).
  • animation-fill-mode: Qué pasa antes/después (forwards, backwards, both).
Buena práctica Para crear animaciones fluidas, animad siempre propiedades que no provoquen reflow del navegador: transform y opacity. Evitad animar propiedades como width, height o margin, ya que causan recálculos de diseño que afectan al rendimiento.

Animación con JavaScript

JavaScript ofrece control total sobre las animaciones. Las principales APIs son:

  • requestAnimationFrame: API nativa que sincroniza las animaciones con la tasa de refresco del monitor (60 FPS). Es la forma recomendada de crear animaciones con JavaScript.
  • Librerías: GreenSock (GSAP), Anime.js y Framer Motion ofrecen interfaces simplificadas para animaciones complejas.
  • DOM manipulation: Modificar directamente los estilos de los elementos con element.style.

SVG y Canvas

SVG (Scalable Vector Graphics) es un formato de gráficos vectoriales que se puede manipular y animar con CSS y JavaScript. Es ideal para iconos, diagramas y animaciones que necesitan escalarse sin perder calidad. Cada elemento SVG es un nodo del DOM que puede recibir estilos e interacciones.

Canvas es un elemento HTML que proporciona un lienzo de dibujo bidimensional. A diferencia de SVG, Canvas dibuja píxeles directamente y no mantiene una representación del DOM. Es ideal para gráficos complejos, juegos y visualizaciones de datos que requieren alto rendimiento.

WebGL

WebGL (Web Graphics Library) es una API de JavaScript para renderizado 3D en el navegador. Permite crear gráficos tridimensionales sin plugins adicionales utilizando la aceleración por hardware de la tarjeta gráfica. Se utiliza en juegos web, visualizaciones científicas, experiencias inmersivas y aplicaciones de realidad virtual en el navegador.

Rendimiento Las animaciones mal optimizadas pueden causar problemas de rendimiento significativos, especialmente en dispositivos móviles. Usad siempre las DevTools del navegador (pestaña Performance) para medir el impacto de vuestras animaciones y asegurar que se mantienen a 60 frames por segundo.

Actividad práctica

Crear una galería de animaciones que incluya:

  1. Un botón con transición de color al pasar el cursor.
  2. Una animación de carga (spinner) usando keyframes.
  3. Un elemente SVG animado con CSS.
  4. Un efecto parallax sencillo usando JavaScript y requestAnimationFrame.

Proyecto final: página web interactiva

Sesión 7 · 50 minutos

Producto de la unidad En esta sesión de cierre vais a crear vuestra propia página web interactiva aplicando todos los conocimientos adquiridos a lo largo de la unidad. Podéis elegir entre Webflow, Google Sites o código puro con editor de código.

Introducción

Es el momento de poner en práctica todo lo aprendido. En esta sesión final vais a diseñar y crear una página web interactiva que demuestre vuestros conocimientos de HTML, CSS y JavaScript. El tema es libre: puede ser una página sobre vuestro hobby, un portfolio personal, un sitio sobre un tema que os apasione o una landing page para un proyecto ficticio.

Opciones de herramienta

  • Webflow: Herramienta visual de diseño web profesional. Permite crear sitios web responsive sin código, pero exporta HTML, CSS y JavaScript limpio. Ideal si queréis centraros en el diseño.
  • Google Sites: Plataforma gratuita de Google para crear sitios web sencillos. Muy fácil de usar pero con menos personalización. Ideal para proyectos rápidos.
  • Código puro (VS Code): Escribir HTML, CSS y JavaScript desde cero. La opción más desafiante pero también la más formativa. Os permite aplicar todos los conceptos vistos en clase.

Requisitos del proyecto

Tu página web debe incluir como mínimo:

  1. Estructura semántica: Uso correcto de <header>, <nav>, <main>, <section> y <footer>.
  2. Contenido multimedia: Al menos una imagen con texto alternativo y un vídeo embebido.
  3. Estilos CSS: Colores coherentes, tipografía legible, espaciados consistentes y al menos un uso de Flexbox o Grid.
  4. Formulario: Un formulario de contacto funcional con al menos 4 campos.
  5. Animación: Al menos una transición o animación CSS en algún elemento.
  6. Responsive: La página debe verse bien en dispositivos móviles y de escritorio.
  7. Accesibilidad: Etiquetas en formularios, textos alternativos en imágenes y estructura lógica de encabezados.
Criterios de evaluación El proyecto se evaluará con la siguiente rúbrica: estructura semántica (25%), diseño visual y CSS (25%), contenido y multimedia (20%), funcionalidad e interacción (20%), accesibilidad y buenas prácticas (10%).

Planificación del proyecto

Antes de empezar a escribir código, dedicad unos minutos a planificar vuestra página:

  • Tema y audiencia: ¿De qué trata vuestra página? ¿A quién va dirigida?
  • Estructura: ¿Qué secciones tendrá? Haced un esquema o boceto.
  • Contenido: Recopilad textos, imágenes y vídeos antes de empezar.
  • Diseño: Elegid paleta de colores, tipografías y estilo visual.

Sesión de trabajo

La sesión se dividirá en las siguientes fases:

  1. 10 minutos: Planificación y boceto del diseño.
  2. 25 minutos: Desarrollo de la página.
  3. 10 minutos: Revisión y pulido de detalles.
  4. 5 minutos: Presentación de los proyectos a la clase.
